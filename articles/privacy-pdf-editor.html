Why build this? Pourquoi ce projet ?

Every time you use Smallpdf, ILovePDF, or any cloud-based PDF tool, your documents transit through third-party servers. For personal documents — contracts, IDs, financial reports — that is an unnecessary risk.

The goal of Privacy PDF Editor is to give full control back: a self-hosted tool that runs entirely on a LAN, where files never leave your infrastructure. The editor handles common PDF operations locally in the browser; the backend on a Raspberry Pi 4 handles encryption, compression, and vault storage.

Pages render 100% locally via PDF.js — nothing is uploaded until you click Export. All JS libraries are vendored: no CDN, no external requests.

À chaque utilisation de Smallpdf, ILovePDF ou n'importe quel outil PDF en ligne, vos documents transitent par des serveurs tiers. Pour des documents personnels — contrats, pièces d'identité, relevés financiers — c'est un risque inutile.

L'objectif de Privacy PDF Editor est de reprendre le contrôle : un outil auto-hébergé qui tourne entièrement en LAN, où les fichiers ne quittent jamais votre infrastructure. L'éditeur gère les opérations PDF courantes localement dans le navigateur ; le backend sur un Raspberry Pi 4 s'occupe du chiffrement, de la compression et du stockage vault.

Les pages sont rendues à 100% localement via PDF.js — rien n'est envoyé avant de cliquer sur Export. Toutes les librairies JS sont vendorisées : pas de CDN, pas de requêtes externes.

PDF Editor Éditeur PDF

The editor is a single-page app that covers the most common PDF operations without ever sending files to a cloud service:

  • Pages: merge multiple PDFs, reorder with drag & drop, rotate, delete, extract. Range shortcuts (1-3,5) for bulk actions.
  • Watermark: tiled diagonal text, configurable opacity and font size.
  • Metadata: live reader showing author, dates, software. Four modes: keep / clear / random (decoy values) / custom.
  • Anonymize: remove active JavaScript and auto-actions; full wipe (XMP + /ID + revision history); rasterize to image for maximum anonymization.
  • Compress: three levels via Ghostscript (if available) or pikepdf.
  • Unlock: remove AES-256 PDF encryption.
  • Privacy scan: real-time detection of author, creation dates, XMP metadata, embedded JavaScript, annotations, form fields, signatures — with a privacy score. Runs 100% client-side.

L'éditeur est une single-page app qui couvre les opérations PDF les plus courantes sans jamais envoyer les fichiers vers un service cloud :

  • Pages : fusionner plusieurs PDFs, réordonner par drag & drop, pivoter, supprimer, extraire. Raccourcis par plage (1-3,5) pour les actions en masse.
  • Filigrane : texte diagonal en mosaïque, opacité et taille de police configurables.
  • Métadonnées : lecteur en temps réel affichant auteur, dates, logiciel. Quatre modes : garder / effacer / aléatoire (valeurs leurres) / personnalisé.
  • Anonymiser : suppression du JavaScript actif et des auto-actions ; nettoyage complet (XMP + /ID + historique de révision) ; rastérisation en image pour une anonymisation maximale.
  • Compresser : trois niveaux via Ghostscript (si disponible) ou pikepdf.
  • Déverrouiller : suppression du chiffrement AES-256 d'un PDF.
  • Scan de confidentialité : détection en temps réel de l'auteur, des dates de création, des métadonnées XMP, du JavaScript embarqué, des annotations, des champs de formulaire, des signatures — avec un score de confidentialité. Fonctionne à 100% côté client.

Métadonnées → effacer / aléatoire supprime /Info mais pas le XMP ni l'historique de révision. Ghost Vault — Plausible deniability Ghost Vault — Déni plausible

The Ghost Vault is the most technically interesting part of the project. It is an encrypted file store where each file supports multiple passwords — each opening a different document. This is plausible deniability: under coercion, you can reveal a secondary password that shows an innocent decoy document, while the real document remains protected.

The vault is a single directory (data/). Each file is an opaque blob that looks like random bytes — no header, no identifiable structure. The file explorer lists all vault files; a password is required to open each one.

Le Ghost Vault est la partie techniquement la plus intéressante du projet. C'est un stockage de fichiers chiffré où chaque fichier supporte plusieurs mots de passe — chacun ouvrant un document différent. C'est le déni plausible : sous contrainte, vous pouvez révéler un mot de passe secondaire qui affiche un document leurre innocent, pendant que le vrai document reste protégé.

Le vault est un seul répertoire (data/). Chaque fichier est un blob opaque qui ressemble à des octets aléatoires — pas d'en-tête, pas de structure identifiable. L'explorateur de fichiers liste tous les fichiers du vault ; un mot de passe est requis pour ouvrir chacun d'eux.

Container format Format du conteneur

BLOB = salt (16 B) + 12 fixed-size cells
├── cell 0 nonce (12 B) + ciphertext (ChaCha20-Poly1305)
├── cell 1 … 10 real documents or random noise
└── cell 11 nonce + ciphertext

Four fixed tiers determine file size: 256 KB, 1 MB, 4 MB, 16 MB. Unused cells are filled with cryptographically random noise. An observer can infer the tier from the file size, but nothing else — not the number of documents, not whether any cell is real or noise.

Quatre paliers fixes déterminent la taille du fichier : 256 Ko, 1 Mo, 4 Mo, 16 Mo. Les cellules inutilisées sont remplies de bruit aléatoire cryptographique. Un observateur peut déduire le palier depuis la taille du fichier, mais rien d'autre — pas le nombre de documents, pas si une cellule est réelle ou du bruit.

Duress mode Mode de contrainte

Each vault file can have a duress password. When used, two things happen atomically:

  1. The decoy PDF is returned to the requester.
  2. The real document's cell is overwritten with random bytes and flushed to disk (fsync) — a cryptographic shred that is unrecoverable, even with disk forensics.
The shred is irreversible. There is no undo. The duress password destroys the real cell permanently.

Chaque fichier vault peut avoir un mot de passe de contrainte. Quand il est utilisé, deux choses se produisent de manière atomique :

  1. Le PDF leurre est retourné au demandeur.
  2. La cellule du vrai document est écrasée avec des octets aléatoires et vidée sur le disque (fsync) — une destruction cryptographique non récupérable, même avec de la forensique disque.
La destruction est irréversible. Il n'y a pas d'annulation. Le mot de passe de contrainte détruit définitivement la cellule réelle.

Cryptography Cryptographie

Every design decision prioritises forward secrecy and resistance to offline attacks:

Chaque décision de conception privilégie la confidentialité persistante et la résistance aux attaques hors ligne :

Key derivation — scrypt

python 
key = hashlib.scrypt(
    password.encode(),
    salt=salt,          # 16 B random, stored in blob
    n=2**15, r=8, p=1,  # ~200 ms on Pi4
    dklen=64
)
chacha_key  = key[:32]   # ChaCha20-Poly1305 key
probe_seed  = key[32:]   # cell probe order seed

The probe_seed determines the order in which cells are tried for a given password — this is what makes each password map to a deterministic, unique cell without any index or lookup table stored in the blob.

Le probe_seed détermine l'ordre dans lequel les cellules sont essayées pour un mot de passe donné — c'est ce qui fait que chaque mot de passe pointe vers une cellule déterministe et unique sans aucun index ni table de correspondance stocké dans le blob.

Encryption — ChaCha20-Poly1305 Chiffrement — ChaCha20-Poly1305

  • Authenticated encryption: tampering with the ciphertext is detectable.
  • 12-byte random nonce per cell, stored alongside the ciphertext.
  • Wrong password: scrypt produces a different key, Poly1305 authentication fails — the cell is simply skipped.
  • Chiffrement authentifié : toute falsification du texte chiffré est détectable.
  • Nonce aléatoire de 12 octets par cellule, stocké avec le texte chiffré.
  • Mauvais mot de passe : scrypt produit une clé différente, l'authentification Poly1305 échoue — la cellule est simplement ignorée.

asyncio offloading Offloading asyncio

scrypt is CPU-intensive (~200 ms on Pi4). Running it directly in an async route would block the FastAPI event loop. All scrypt calls are offloaded to a thread pool via asyncio.to_thread.

scrypt est gourmand en CPU (~200 ms sur Pi4). L'exécuter directement dans une route async bloquerait la boucle d'événements FastAPI. Tous les appels scrypt sont déportés dans un pool de threads via asyncio.to_thread.

python 
# Non-blocking — event loop stays free during KDF
pdf = await asyncio.to_thread(vault_store.open_file, file_id, password)

Architecture

Three components, all LAN-only. The frontend never makes requests to external services; the backend never writes decrypted content to disk.

Trois composants, tous en LAN uniquement. Le frontend ne fait jamais de requêtes vers des services externes ; le backend n'écrit jamais le contenu déchiffré sur le disque.

Browser (PC — python -m http.server 3000)
├── PDF.js renders pages locally — no upload until Export
└──► FastAPI backend (Pi4 — port 8000)
├── POST /api/organize merge · watermark · anonymize · compress
├── POST /api/unlock remove PDF password
└──► Vault routes
└──► data/ opaque blobs on disk

Security headers En-têtes de sécurité

python — FastAPI middleware 
response.headers["X-Content-Type-Options"] = "nosniff"
response.headers["X-Frame-Options"]       = "DENY"
response.headers["Referrer-Policy"]       = "no-referrer"

Every PDF upload is validated against the %PDF magic bytes before processing. Passwords are rejected below 8 characters. CORS is restricted to LAN origins.

Chaque upload PDF est validé contre les magic bytes %PDF avant traitement. Les mots de passe de moins de 8 caractères sont rejetés. Le CORS est restreint aux origines LAN.

Frontend (PC) Frontend (PC)

bash

Open http://localhost:3000, set the backend URL to http://<pi-ip>:8000 and save. The indicator turns green when the Pi responds. The backend URL is stored in localStorage — no config file needed.

No Node.js, no npm, no build step required to run the frontend. The JS libraries (PDF.js, SortableJS) are vendored in frontend/lib/ and committed to git.
